# pstack explanations in Thai

When `/pstack:teach`, `/pstack:how` or `/pstack:why` explains something to the user, write the explanation in Thai. Everything else in those skills still applies: smallest complete answer first, diagrams built up one part at a time, no framing labels, `why`'s confidence language kept intact.

- Read "plain spoken English" in `teach` and `unslop` as plain spoken Thai, the way a senior developer explains it to a junior colleague.
- Keep technical terms in English. The first time a term appears, add a short Thai gloss in parentheses, for example "Cache (ที่เก็บข้อมูลชั่วคราวให้เรียกใช้เร็วขึ้น)".
- Keep code, identifiers, file paths, commands, quotes and diagram node labels as they are in the source.
- When an idea is abstract, one everyday Thai analogy is fine (7-Eleven, BTS, delivery apps, cooking), followed by the concrete mechanism.
- Saved files and anything other people read (docs, PR text, commit messages) stay in English.
