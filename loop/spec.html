Loop Engineering บน Claude Code

Coordinator → Worker (1 herdr session ต่อ 1 task) → Reviewer → Draft MR → คุณ verify ขั้นสุดท้าย · launchd + claude บน Mac · task อยู่ใน Workspace

1. Goal

ระบบวนทำงานเองทุกวันตอน 9:15 หยิบ task ของคุณใน Workspace ที่ข้อมูลชัด (ทำได้ถึง risk:high และรายงาน risk ทุกใบ) ทำพร้อมกันได้ 2 ใบ จนได้ Draft MR ที่มี evidence ครบ รอคุณ verify คนที่สั่ง merge มีแค่คุณ (ระดับ L2)

เรื่องค่า
แหล่งงานWorkspace (MCP workspace) · space ตาม ~/loop/workspace.md · assignee = คุณ
routingfield route (agent/human) + label risk: type: needs:human
repo ที่ Worker แตะได้ทุก repo ใน ~/loop/repos (รายละเอียดใน ~/Home/docs/repo-map.md)
MRDraft เข้า base branch ของ repo · label owner:you + needs:human-verify (+ needs:e2e ถ้าแก้ UI)

2. Flow

Triage (headless, opus)

  • /loop-triage อ่าน task ด้วย query_view ตั้ง route และ label ให้ใบที่ยังไม่ triage ไม่ย้าย status ไม่แก้ description
  • ใบที่ข้อมูลไม่ชัด → route=human + needs:human + comment คำถาม (mention เฉพาะเจ้าของ card) และขึ้นในตาราง "ต้อง grill ก่อน Agent เริ่มได้"
  • เลือกได้ไม่เกินจำนวน Worker slot ที่ว่าง (LOOP_MAX_WORKERS, ค่าเริ่ม 2) เรียงตาม release ใกล้สุด → priority → เก่าสุด

Worker (herdr session, opus คุม · sonnet เขียนโค้ด)

  • loop-run.sh สร้าง worktree บน branch loop/<task> (ไม่ตั้ง upstream) แล้วเปิด herdr space loop <task> ที่รัน /loop-work แบบ interactive เข้าไปดูหรือสั่งต่อได้
  • ลำดับ: start_work + In Progress → TDD → verify ผ่าน loop-heavy (build/test ทีละตัวทั้งเครื่อง) → agent loop-reviewer (read-only) → แก้ findings → loop-push → Draft MR → add_task_link + In Review → comment handoff → finish_work
  • repo ที่ยังห้าม agent push → หยุดที่ branch ในเครื่อง แล้ว comment คำสั่ง push / เปิด MR ให้คุณ
  • ข้อมูลไม่ชัดระหว่างทาง → หยุด, comment คำถาม, needs:human

Summary และ gate ของคุณ

  • 9:30 loop-summary แสดงสรุปรอบล่าสุด งานค้าง และ task ที่ต้อง grill
  • คุณ verify ตาม checklist ใน comment → /loop-e2e (ถ้าแก้ UI) → /merge-approved ถ้าต้องแก้: ปิด MR แล้วรับงานต่อเอง

3. Guard rails

  • ห้ามอ่าน .env* / .npmrc / secret ห้ามแตะ production config ห้ามรัน migration กับข้อมูลจริง
  • git push ตรง ๆ ถูก deny ทั้งหมด push ได้ผ่าน loop-push เท่านั้น ซึ่งปฏิเสธ branch ที่ป้องกันไว้ และไม่รับ refspec หรือ force
  • ห้าม merge, approve, rebase, reset และห้าม merge เอง
  • comment ของ Loop ขึ้นต้นด้วย 🤖 [loop-status] และ post ใหม่เฉพาะตอนมีเหตุการณ์ (MCP ยังแก้ comment ไม่ได้)
